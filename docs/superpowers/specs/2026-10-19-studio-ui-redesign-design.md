# Studio UI 系统重设计

> 状态：完整设计与八任务实施计划均已于2026-10-19获用户批准。A · Studio为唯一设计方向；产品实施按已批准计划进行。
>
> Route: openspec+superpowers。当前 owner: implementation。变更为`openspec/changes/studio-ui-redesign/`；不得扩展到数据库、依赖、持久化或原生播放器改造。

## 1. 目标与已确认方向

用户反馈是“整体的设计都很一般”，要求分析并系统重设计，而非修补单个页面。比较两个独立 HTML 原型后，用户于 2026-10-19 明确选择 **A · Studio**。

Studio 的主线：音乐内容优先、导航稳定、表面克制、操作有层级。辨识度来自封面、排版和低饱和绿色，而不是大品牌标题、重卡片、常驻导入说明或多层玻璃。

用户先确认方向A，随后批准本文完整设计进入OpenSpec规格和实施规划；不将该批准解释为实施计划也已获批。

### 现状依据

| 依据 | 发现 | 设计响应 |
| --- | --- | --- |
| 实际启动 macOS 应用，观察 800×600 窗口 | 已有音乐时仍有较大导入提示；品牌、入口与分类推迟首排专辑出现 | 非空资料库以内容开场，导入变为按需入口 |
| 同一窗口及 `LibraryHomeContent.kt` 的宽布局 | 左列拥挤，右列未选择详情时大面积占位；固定比例不能保证空间有效利用 | 按可用宽度与当前任务展开详情，不保留空详情栏 |
| 实际桌面迷你播放器及 `NowPlayingBar.kt` | 搜索、设置与播放身份挤在持续显示的区域 | 导航独立；迷你播放器只负责当前曲目与播放 |
| `LibraryRows.kt` 的六项分类和行容器 | 窄布局缩小分类文字，歌曲行又采用较重卡片 | 用视图入口承载分类；歌曲采用连续行 |
| `core/ui/.../theme/Theme.kt` | 现有公共主题以七种颜色为主 | 在现有 core UI 所有权下补齐语义色、排版、间距、密度与状态规则 |

源码位置完整前缀：Library 为 `feature/library/impl/src/commonMain/kotlin/com/eterocell/rhythhaus/library/ui/`；Now Playing 为 `feature/nowplaying/src/commonMain/kotlin/com/eterocell/rhythhaus/nowplaying/`。除资料库与迷你播放器的桌面实际观察外，不将源码审查描述为设备视觉验收。

### 成功标准与反目标

- 360dp 宽、640dp 高且默认文字比例的紧凑窗口，非空资料库的首排专辑可见；导入引导不占据常驻大块高度。
- 800×600dp 窗口不显示无选择的空详情列；主内容不需要通过缩小导航字体来容纳。
- 六种现有资料库视图均保留且至多两次点击可达；设置、搜索不依赖当前是否有播放曲目。
- 歌曲、搜索、播放列表与队列共享行与动作层级；不存在每页各自发明的圆角、按钮和文本样式。
- 播放、选择、返回、扫描与来源操作的既有语义不变；新外观不能引入第二套业务状态或 Back 权威。
- 不加入推荐、流媒体、账号、联网封面/歌词、均衡器、输出设备选择或新的音乐管理能力。
- 不照搬 HTML 原型为 Compose 实现；原型封面是概念插画，曲目数量、年份、时长与歌词示意不是真实数据库证据。

## 2. 信息架构

三个主目的地：**资料库、搜索、播放列表**。设置为全局工具入口，不作为播放控件。

| 区域 | 负责 | 不负责 |
| --- | --- | --- |
| 资料库 | 专辑、艺术家、歌曲、收藏、最近播放、最近添加；现有排序/筛选；详情与选择 | 常驻扫描报告、来源恢复与破坏性维护 |
| 搜索 | 现有标题/艺术家/专辑字段的歌曲匹配；搜索结果按现有可见顺序播放 | 新增专辑/艺术家实体搜索、联网搜索、持久搜索历史 |
| 播放列表 | 静态/智能列表、创建/编辑/删除、既有导入导出和备份 | 临时队列的默认宿主 |
| 当前队列 | 当前及后续播放上下文；现有重排/移除/清空；保存为播放列表 | 自动变成永久列表或重新定义队列语义 |
| 设置 | 外观、播放偏好、来源与扫描、备份与维护、关于 | 依赖播放选中状态的导航入口 |

### 紧凑导航

- 底部三项固定顺序：资料库、搜索、播放列表；图标与文字同时显示。
- 资料库顶端显示“专辑 / 歌曲 / 艺术家”。同行或紧邻的“收藏与最近”入口打开收藏、最近播放、最近添加三个具名选项；不能只有无名省略号，也不再将六项缩成极小文字。
- 选中收藏或最近视图后，当前标题显示完整视图名称；可从同一视图选择器返回其他视图。该入口在滚动顶部可发现，桌面侧栏对应独立项目。
- 设置齿轮位于各主目的地的顶栏同一位置；详情页保留返回，不用齿轮替换返回。
- 未选择任何播放曲目时不伪造迷你播放器；歌曲暂停但仍为有效选中曲目时继续显示。
- 多选期间用选择上下文栏替代浏览动作和底部播放操作，避免两组行动条叠压；播放本身不被停止。退出与返回遵循现有 Shared 仲裁。

### 主入口切换与状态生命期

设计者决定保留当前 **Home为根的单栈**，不在此次外观重设计中引入三个独立的保留根栈。底部与侧栏是稳定主入口，不宣称具有新的多栈导航语义。

- 点击资料库复用现有Home动作，回到根并移除其上路由；不承诺恢复刚离开的专辑详情。
- 点击搜索或播放列表复用普通路由push；与当前精确路由相同则不再入栈，不创建重复页面。
- 例如“资料库→专辑→搜索→播放列表”之后，在无弹层/选择等优先目标时，Back依次回到搜索、专辑、资料库；此时点资料库则直接回根。已退出栈的搜索或详情不另建后台缓存。
- 当前主入口高亮来自实际路由所属领域；设置/关于/引导不伪装成第四个根目的地，也不错误高亮搜索或列表。
- 返回到仍在栈中的同一destination时，查询、滚动与局部状态延续现有生命期；真实路由进入/退出仍按现有规则结束编辑并清除页面选择。仅调整窗口或重排同一destination时不清除选择。

依据：`shared/src/commonMain/kotlin/com/eterocell/rhythhaus/library/ui/LibraryNavigation.kt`中的`LibraryNavigationStack.push/popToRoot`，以及同目录`LibraryAppShell.kt`中的`pushRoute/openDetailRoute`。此决定避免重设计暗中变成导航架构项目；若未来要多栈恢复，需要另行批准。

### 桌面导航

- 展开侧栏显示资料库、搜索、收藏、最近播放、最近添加、播放列表；设置与音乐来源管理入口位于侧栏底部。
- 中等宽度允许缩为具备工具提示及无障碍名称的导航轨；收起只是布局，不新建目的地状态。
- 队列入口位于播放器。播放列表页不再以“当前队列 / 已保存”作为一级分段；原有保存队列操作迁到队列面板。
- 调整已有入口属于本次呈现重设计；不改变静态/智能列表格式、保存队列范围、重复曲目或播放事务。

## 3. 布局与尺寸

以下是建议的逻辑 dp，按实际内容区域计算，不以设备型号判断。字体放大与本地化优先于固定列数。

| 内容宽度 | 外壳 | 资料库与详情 | 播放器 |
| --- | --- | --- | --- |
| <720dp | 底部三导航，16dp 页边距 | 单任务单列；专辑自适应网格；详情整页进入 | 全屏覆盖，封面上、核心控件下 |
| 720–999dp | 80dp 导航轨，24dp 页边距 | 默认单内容区；选择专辑/艺术家后进入详情，不保留空详情栏 | 宽高足够才左右分栏，否则纵向 |
| ≥1000dp | 208dp 侧栏，32dp 页边距 | 未选择详情时内容占满；选择后，浏览列至少320dp、详情至少400dp、间隔24dp；不足则回退单任务 | 封面与核心控制左右排列；有剩余至少280dp才显示队列侧栏 |

- 超宽窗口正文最大宽度 1440dp，居中；允许内容自身滚动，不放大所有字号与封面填满空白。
- 专辑网格以紧凑最小128dp、宽屏最小160dp的卡宽和16/20dp间距计算列数；不得以缩小文本强行维持列数。标题至多两行，艺术家一行，完整内容由无障碍标签及详情提供。
- 歌曲行建议64dp高、48dp封面；桌面默认56dp行、40dp封面。它们是最小值，文字放大时允许增长。
- 迷你播放器：紧凑64dp，桌面80dp；避开系统安全区。正文底部必须为其和导航预留空间，不透明遮住最后一行。
- 紧凑播放页按可用高度收缩封面而非缩小播放目标；竖屏短高或大字模式允许次级内容滚动，核心控制优先可达。
- 旋转、调整窗口或对同一destination重新排版不能重置其浏览视图、排序、筛选、滚动位置、页面选择或当前曲目。真实进入/退出详情依照上节的路由生命期：允许现有的清除选择/结束编辑，不新增跨页面选择持久化；浏览投影与仍存活页面状态按原有规则保留。

## 4. 视觉与组件规范

### 语义颜色

不再让 pulse 同时承担主操作与危险操作。初稿色值如下；实现按对比度标准验收，不以肉眼“看起来差不多”替代。

| 角色 | 浅色 | 深色 |
| --- | --- | --- |
| 页面背景 | `#F9FAF7` | `#171E1A` |
| 标准表面 | `#FFFFFF` | `#202923` |
| 导航/次级表面 | `#F2F4EE` | `#1C251E` |
| 主文字 | `#253129` | `#E5EADD` |
| 次级文字 | `#65715F` | `#A5B09F` |
| 主操作/选中 | `#3C6148` | `#BFD0AA` |
| 主操作上文字 | `#FFFFFF` | `#182217` |
| 选中浅表面 | `#EAF0E5` | `#303E2F` |
| 装饰分隔 | `#DEE3D8` | `#394434` |
| 交互边界 | `#84917D` | `#7E8E74` |
| 危险操作 | `#B13B32` | `#FFABA2` |
| 危险浅表面 | `#FBEAE7` | `#462824` |
| 危险按钮上文字 | `#FFFFFF` | `#321A18` |
| 警告 | `#805D13` | `#E7C976` |

- 正常正文对背景至少4.5:1；大文字、图标、焦点与必要交互边界至少3:1。装饰分隔线无需冒充交互边界。
- 危险动作同时使用明确动词与图标/文案，不能只变红；选中、播放、收藏也不能只用颜色表达。
- 保留系统/浅色/深色三种现有主题设置。初稿原型未做全部对比度与大字校准，正式 token 以本文和验收为准。
- 背景采用实体表面。玻璃不作为功能分区或默认容器；减少现有装饰性模糊不改变手势、Back 或动画结算权威。

### 排版、间距与形状

- 使用平台系统无衬线字体与现有中英文资源，不引入字体依赖或联网字体。
- 页面标题28sp/34行高、半粗；紧凑标题24sp/30；区块标题18sp/24；歌曲标题及正文16sp/22；次级文字14sp/20；辅助标签12sp/16。正文导航不得低于12sp。
- 字重以常规与半粗为主，不将标题、按钮、辅助说明全部加粗；英文长标题和中文换行均须验证。
- 间距采用4、8、12、16、24、32、48dp，尽量消除局部魔数。
- 封面圆角8dp；输入/按钮10dp；低频分组表面12dp；弹层20dp。歌曲行没有独立重圆角外卡片。
- 主按钮最小48dp高；移动端触达至少48×48dp，iOS不低于44pt；桌面图标视觉可紧凑但键盘与指针目标必须可用。
- 复用已有矢量图标；导航带标签；不使用 emoji 控件。

### 组件层级

`页面外壳 → 顶栏/工具栏 → 内容 → 上下文动作/播放器 → 按需弹层`。

仅跨特性复用的排版、语义色、按钮、输入、列表行、空态、弹层壳属于 `:core:ui`；领域内容与行为留在各 feature。具体 Kotlin 符号、内部实现和参数由计划决定，本文不建立新的导出 API 或第二套主题系统。

## 5. 页面与交互

### 资料库与详情

- 非空页：标题/数量 → 当前视图与排序筛选入口 → 内容。不要插入巨大品牌标题、全宽播放列表跳转或始终存在的导入卡。
- 保留全部现有排序方向、收藏/封面/来源筛选及各视图适用范围。启用条件以具名标签显露，可单项清除或清除全部；不新增保存预设。
- 收藏与最近视图不复制业务数据；继续消费权威投影。最近添加仍使用既有创建时间。
- 专辑/艺术家详情：封面与标题 → 现有播放/选择等动作 → 连续歌曲行。曲目点击仍以该可见有序结果建立播放上下文。
- 歌曲主点击播放，长按进入选择；桌面提供右键/更多的等价动作。收藏可见但次于标题；编辑等低频动作进入更多菜单。
- 元数据编辑保留应用内覆盖、不写原文件、恢复原值语义；显示扫描原值与当前覆盖的区别，取消不能保存草稿。
- 无封面时用稳定的中性音乐图形与可读身份信息，不用概念插画冒充真实封面，不触发联网获取。

### 搜索

- 搜索页先显示搜索框；空查询保持现有“不显示全部歌曲”的语义，提供简短本地字段提示，不新增历史存储。
- 输入后显示匹配数量及统一歌曲行；命中规则、大小写处理和播放顺序沿用现有实现。
- 无结果说明当前查询，给清除查询动作；不要误导用户导入、重新扫描或断言文件丢失。
- 返回保留现有路由生命期的查询/滚动状态；键盘与内容安全区不遮挡当前操作。

### 播放列表、智能规则与队列

- 播放列表页列出静态与智能列表，用文字/小图标区分类型；主创建动作先选择已有的静态或智能类型。
- 静态列表保留命名、重排、移除、删除、选中加入、JSON备份、M3U/M3U8/PLS互操作；既有可用入口均须迁移，不将导出误标为备份。
- JSON维持导出全部静态列表、校验与无写入预览、唯一/未匹配/歧义计数、过期预览拒绝、原子恢复和取消语义。互操作维持单个静态列表与显式M3U/M3U8/PLS格式选择、元数据匹配预览和原子导入；路径不授予来源访问。两个流程复用现有系统文档桥，取消或失败后可再次操作；不能合成一个含糊的“备份”按钮。设置原有文档入口保留，播放列表页的对应入口委托同一操作所有者，不创建第二个并发门禁。
- 智能列表保留已支持的单规则与参数，不新增 AND/OR、规则组合、自动推荐或重复策略。
- 规则编辑分两步视觉分组：选规则，再显示其所需参数；艺术家/专辑/来源列表可独立滚动，底部确认不被长列表挤走。窄屏使用近全高弹层，宽屏为有约束宽高的对话框。
- 智能与静态的 JSON备份差异须保留既有说明；失效来源使用已有恢复/空态语义。
- 队列在完整播放器由具名入口展开：紧凑为近全高弹层，宽屏优先侧栏。展示当前项与接下来；现有可访问的其他队列段不被删去。
- 保存队列仍捕获原有“当前及后续”范围、顺序和重复 occurrence。取消、异步确认、旧响应保护沿用现有事务。
- 更改队列或播放列表外观不改变正在播放的选择事务，不新增双击播放、隐式替换队列等手势。

### 迷你播放器、完整播放器与歌词

- 紧凑迷你播放器：封面、标题/艺术家、播放暂停、空间允许时下一首；点曲目身份展开，播放按钮不触发展开。桌面加独立队列入口；音量仅保留真实已有能力，不把原型滑杆解释为新增功能（见第10节源码校正），不放搜索和设置。
- 完整播放页只有一组主播放控制，不能在页底又重复完整 transport。顺序为封面、曲目身份/收藏、进度、上一首/播放暂停/下一首、次级动作。
- 随机和循环显示清楚的现有状态与无障碍语义；进度拖动、点击跳转、时间显示沿用既有 scrubber 合约，不更改恢复和播放时机。
- 定时、队列有固定具名入口；歌词入口位置固定但仅在当前曲目具有非空本地歌词时出现，无歌词时不显示空动作或空歌词页。歌词保持本地 sidecar/内嵌来源与原有优先级，保留纯文本、时间轴和已支持的错误语义；不使用示意歌词作为正式内容。
- 歌词是播放器内的阅读目的地；返回先退出歌词再收起播放页。定时/菜单等临时弹层先于下层内容处理返回；具体顺序必须符合 Shared 既有权威，而非 feature 自行消费平台 Back。
- 睡眠定时保留既有时间/当前曲/N首、淡出、取消与状态；开启时在入口显示简短状态，不隐藏在颜色变化中。
- 播放失败保留结构化错误和现有重试、跳过、仅从队列移除；不得以关闭弹层或隐藏错误当作修复。

### 设置、来源管理与关于

设置按五组呈现，不制造平行存储：

1. 外观：系统/浅/深主题。
2. 播放：ReplayGain模式、crossfade时长、gapless模式、自动恢复策略和真实输出状态。每项保留现有选项、保存中/保存失败状态及动作门禁，不把三个不同偏好压成含糊的“播放衔接”开关。循环/随机仍属于播放器会话控制，不另加Settings偏好副本。
3. 音乐来源：添加、扫描、取消、来源访问恢复、扫描摘要与移除缺失。扫描结果保留上次完成与当前失败/取消的区别。
4. 备份与维护：既有列表备份/恢复入口、封面缓存清理；清空资料库与移除来源等危险操作与日常偏好分隔。
5. 应用信息：重新查看引导、关于、开源许可。

输出状态仅报告已验证的活动路由，否则说明不可用；本次不加入路由选择。缓存清理不删媒体或资料库。通知拒绝恢复仅在适用 Android状态显示，iOS Files.app文案只出现在iOS对应位置。

来源移除、清库、移除缺失等确认页明确影响对象、数量（仅在真实可得时）、是否影响原文件和不可逆性，沿用实际仓库语义，不凭设计假定“安全可撤销”。操作冲突与扫描取消/等待状态沿用 App 协调器，不靠UI双重门禁重写规则。

## 6. 完整状态与优先级

| 场景 | 呈现 | 可用下一步/约束 |
| --- | --- | --- |
| 首次空库 | 一段说明 + 一项平台准确的主导入动作 | 使用现有 picker/权限桥；引导可跳过，不强制授权 |
| 非空且正在扫描 | 顶部紧凑进度/状态 + 内容继续可用 | 详情/取消走既有扫描动作；报告在设置 |
| 当前视图无项目 | 指明收藏/最近等视图为空 | 返回其他视图；不声称整个资料库为空 |
| 已启用筛选但无结果 | 明示启用的条件 | 清除筛选；不能误导重新导入 |
| 来源不可访问 | 具名来源状态与真实恢复动作 | 不把不可访问等价为媒体已删除 |
| 扫描失败/取消 | 终态与最近完成报告区分 | 重试仅复用已支持动作，不伪造完成进度 |
| 无选中曲目 | 不显示迷你播放器 | 主导航完整可用 |
| 播放加载 | 保留身份，核心控件按真实可用性显示 | 不把加载误画为已播放，不重复提交播放 |
| 暂停/播放/结束 | 明确图标、标签与当前项 | 以权威播放状态为准，不由动画推断 |
| 播放失败 | 曲目附近的解释 + 现有恢复操作 | 保留队列上下文，不隐式删媒体 |
| 无封面/长标题/缺失标签 | 中性回退与可读文本，适当换行 | 艺术家/专辑缺失使用既有本地化回退 |
| 选择/编辑 | 选中数量与上下文动作，明确取消 | 只呈现当前可执行动作；不与播放器重叠 |
| 确认/进行中/失败 | 一个提交状态及就地错误 | 避免同帧重复提交；取消不能使旧响应作用于新界面 |

不使用透明度来“禁用”仍可点击或仍被读屏发现的退场界面。非活动层必须移除交互与无障碍动作；焦点停留在最高有效层，关闭后回到原入口。

## 7. 无障碍、输入与动效

- 移动端触达与桌面键盘焦点独立验收。图标按钮具有动作名称与选中/开启状态；播放页按曲目、进度、核心控制、次级控制的顺序朗读。
- Tab顺序跟随视觉任务顺序；Enter/Space激活；Esc/平台Back进入现有仲裁，不在 feature 新装全局处理器。
- 键盘搜索快捷键仅在宿主已有可实现能力的计划范围内接入；预览的“⌘ K”不是既有实现证据，不能在正式UI展示未接通的快捷键。
- 长按选择有更多菜单/明确选择动作的等价路径；拖拽重排有既有可访问替代，不把拖拽作为唯一操作。
- 字体200%时不丢失播放、返回、确认与错误动作；EN/ZH、无封面、极长标题、横屏短高必须验证。
- 动效建议150–220ms，用于状态反馈和层级连续性。系统减少动态效果时取消大幅位移/缩放；不修改已有预测Back的结算协议。
- 所有新文案进入所属特性的EN/ZH资源，不把品牌式英文副标题强制用作中文操作提示。

## 8. 代码所有权与切换约束

- 保持 Kotlin/Compose Multiplatform、现有 Miuix 基础组件和 Gradle 工具链。不因外观选择引入WebView或新UI库。
- `:core:ui` 只持有跨功能呈现规则；资料库、搜索、播放列表、Now Playing、设置/引导分别保留所属 feature。`:shared`仍为外壳、路由与跨特性装配根。
- 本次不接纳 `replace-shared-back-with-miuix-nav` 的未完成导航架构提案；不复活 roadmap 已放弃的 `adopt-miuix-navigation-runtime`。沿用当前实际可运行的 Shared Back/presentation权威。
- 不改变数据库schema、播放引擎、扫描协调、iOS导入ABI、媒体文件、CarPlay模板/系统媒体外观或平台权限所有权。
- 以完成的 feature切片替换旧呈现，迁移所有调用点与相应测试/文案，不长期保留A/B主题分叉、旧外壳别名或两套按钮系统。

## 9. 建议落地顺序与验收

这是设计分阶段边界，不是可直接执行的实现计划。全文批准后由OpenSpec与writing-plans细化文件、任务和证据。

这是用户新提出的呈现重设计，不是Phase 2–4功能尚未完成的前置条件。roadmap既有Phase 1实体设备/系统控制验收继续保留，不将重设计审批或HTML烟测记为这些验收通过，也不重新打开已完成的功能实施。

1. **统一基础与外壳**：语义token、排版/尺寸、公共交互、三目的地导航、播放器停靠与尺寸回退；验证所有现有页面仍可达。
