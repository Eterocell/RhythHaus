# C · 平台自适应完整视觉重设计

> 状态：设计基线已获用户批准；实施计划仍待单独批准。用户已选择 C 方向、接受 Monet 可选且默认保留 RhythHaus 色板，并确认完整视觉重设计范围；当前由助手负责生成完整逐页高保真设计稿与正式色值表。
>
> Route: openspec+superpowers。当前 Owner: Superpowers / design。本轮不改产品代码，不修改旧 Studio 设计/验收记录，不将 HTML 原型的结果作为 Compose 或设备验收。

## 1. 为什么重新设计

用户指出三项实际体验问题：多个页面 Insets 不正确，甚至转场与静止位置不同；完整播放器不再能直觉地下滑关闭；深浅模式各只有一套色彩系统，缺少选择与 Android Monet。用户要求的不只是三处修补，而是从设计稿开始完整重设计。

设计原则：**平台各有表达，内容边界始终一致。** 保留共享 Compose、现有业务行为与 feature-first 所有权；重做页面层级、组件、状态、动效和平台外壳适配。不把「平台自适应」解释为分别重写三套原生 UI。

### 已确认与设计者决定

| 项目 | 依据与状态 |
| --- | --- |
| 方向 C、完整视觉重设计 | 用户明确选择；不是继续保留 A 外观的定点修补 |
| Monet 可选、RhythHaus 色板为默认 | 已向用户明确解释其 OK 的含义，随后获准继续完整重设计 |
| 苔绿、海湾蓝、陶土、鸢尾紫四套色板 | 现有 C 原型中的设计提案；具体语义 token 由本设计约束，不把示意 CSS 当正式值 |
| 单栈导航、业务层不重写 | 延续现有产品合约；本次不引入独立底部多栈 |
| 尺寸、手势仲裁、保存失败策略 | 以下由设计者明确提出，随本文一起审批；不是声称用户逐项指定 |

### 事实与尚未确认的根因

- `core/ui` 的公共主题及 Shared 的偏好装配是现有主题入口，System/Light/Dark 是明暗模式，不等于多色板。
- Shared 外壳和部分 feature 页面均有 Insets 处理。例：Settings 的 `Scaffold` 使用零 content insets，但内部列表另用 `safeDrawing` 的上方/水平方向。
- Android Activity 使用 edge-to-edge；iOS 的 Swift Compose 宿主使用 `ignoresSafeArea()`。原生边缘延伸与 Compose 安全区不能各加一遍。
- 播放器源码仍存在下滑路径；用户报告实际不可用是本轮行为依据，不能据此认定只是缺少把手。实施前必须按 systematic-debugging 复现输入路径并定位根因。
- Insets 处理分散是风险证据，不是已经证明了每个动画跳变的根因。计划必须先记录真实页面、静止/转场位置与消费链，再做单一归属修正。
- 当前 Android minSdk 29，动态取色只在支持它的 Android 12 / API 31+ 提供，不抬高最低版本。

## 2. 方案取舍与范围

曾比较 A 固定内容框、B 沉浸式边缘画布、C 平台自适应；用户选择 C。A 容易统一但弱化平台差异，B 强调边缘延伸却增加安全区与交互冲突风险；C 保留平台窗口特征，同时让每个平台内部的边界稳定。

实施范围也比较过定点修补与完整重设计：前者保留旧页面结构、风险较低，却不能解决整体设计不满意；用户选择后者。保留业务与共享 Compose 是本方案的边界，不是另加的业务重写。

**目标**：全部现有应用内页面使用同一套视觉与交互规则；安全区在转场全程正确；播放器可发现且可靠地下滑收起；四套完整明暗色板与 Android 可选动态色；紧凑、导航轨、桌面侧栏均可用。

**不做**：播放/扫描/数据库重写，新权限或媒体来源、推荐、联网歌词/封面、账号、云同步、均衡器、输出设备选择、Windows/Linux 支持。CarPlay 模板与系统媒体控件不做视觉重设计，原有功能与验收保留。

**失败判定**：只改示例截图中的页面；只替换 accent 而留旧表面色；动画途中补另一套 padding；隐藏错误当修复；下滑只能抓细把手；缩小触达区以塞进布局；牺牲既有入口、队列草稿或 Back 语义。

## 3. 安全区与转场：先定义归属

### 外壳、页面与浮层

| 层 | 唯一职责 | 禁止事项 |
| --- | --- | --- |
| 平台宿主 | 报告真实窗口、cutout、系统栏、键盘与桌面标题栏环境；允许背景延伸到边缘 | Swift/Activity 与 Compose 重复预留同一安全区 |
| Shared 外壳 | 将平台值转换为可用矩形，摆放导航、顶栏、停靠播放器；向页面传入明确已消费的边界 | 使用「动画中」布尔值改变 Insets 归属；feature 通过服务定位器读取外壳依赖 |
| Feature 内容 | 在传入可用矩形内排版、滚动；拥有设计页边距和内容间距 | 再次读取全窗口 safeDrawing 给同一边加 padding；把固定页边距当系统栏高度 |
| 全屏播放器/弹层宿主 | 对自身覆盖的窗口处理安全区、焦点与输入；向浮层内容传递可用范围 | 在已经缩进的父容器上再次叠加整窗 safe area |

全屏背景可以画进系统区，按钮、文本输入、播放控制和关键内容不进入遮挡区。每条边只消费一次；避免「一律删掉 Insets」这种对 cutout/横屏/浮层失效的修补。

- Android：状态栏、显示缺口、手势或三键导航均使用实际测量值；系统栏前景明暗跟随当前可见表面，不产生一帧错误颜色。
- iOS：保持全窗 Compose 宿主；交互区避开刘海、灵动岛、横屏缺口和 Home indicator。不是使用原型里的固定 46/28px。
- macOS：使用实际内容窗口与标题栏边界，不模拟手机状态栏，不在正文再加一层移动端底部安全区。
- 横屏的左右安全区与左右侧栏占用同样纳入可用宽度；不能仅修正 top/bottom。

顶栏采用一个 Shared 持有的公共宿主，由当前 route 通过显式契约提供标题、返回与有效动作；feature 不再各自插入带系统安全区的顶栏。Search 输入框、Library 分类/筛选位于内容区，公共栏不承担搜索编辑状态。旧详情的封面折叠可以保留为 feature 内容内部的滚动效果，但不再驱动系统区或公共顶栏的高度/透明度；不保留跨安全区的大标题折叠行为。Shared 拥有顶栏测量与内容框分配，feature 拥有自身滚动状态，避免建立跨层 nested-scroll 权威。公共标题不与内容中的相同页面大标题重复。

### 稳定的内容框

- 在同一窗口状态下，转场前、中、后的来源/目标页使用相同的外壳可用矩形和相同系统 Insets。允许内容做有意位移，不允许起始/结束时重新测量出另一套基准。
- 系统区、导航与停靠播放器不参加路由内容的进退场动画。顶栏高度固定在当前布局约束内；标题/返回/动作随路由切换，但不通过双层顶栏挤压内容。顶栏标题统一单行且使用同一字号/行高，长标题省略显示但保留完整无障碍名称，专辑/艺术家完整身份在详情正文可读。顶栏高度由当前布局类、系统文字比例、单行文字与触达目标共同测量，与当前 route 的标题长度和动作数量无关；动作过多进入具名更多菜单而非撑高栏。大字会让同一布局类的所有路由使用相同增高后的栏，不为某个长标题单独增高。旋转/字体设置真实变化时统一重测；固定窗口与字号下不会在进出路由时改基准，也不为转场临时预留较高栏再撤掉。
- Settings/About 等无播放停靠栏的工具页面可使用其自己的完整内容范围。与有停靠栏页面切换时，两端的目标布局在转场前确定；底部栏由外壳独立退出，不能先给目标预留旧栏高度、动画结束再撤掉。这里允许设计性的底部占用差异，不允许把它误算为系统 Insets 变化。
- 预测 Back、交互取消、快速连续 push/pop 使用同一归属规则；取消后恢复原路由与布局，不残留位移、焦点或触控遮罩。
- 屏幕旋转、窗口尺寸和系统 Insets 真正变化时重新布局所有活跃层；不会为了「稳定」冻结过期值。
- 滚动页面尾部预留真实导航、停靠栏、选择操作栏所占空间。只在叠放时累加占用；不是把已避开的内容再加一遍高度。

### 键盘与覆盖层

搜索、重命名、规则参数及元数据编辑都避让 IME；底部遮挡按实际相交区域处理，不能把重叠的 IME 与系统底栏高度简单相加。键盘出现时紧凑播放停靠栏/底部主导航暂时隐藏，编辑确认保持可达，键盘关闭后恢复；不改变播放。IME 的真实变化可以引发布局动画，不能被当作路由 Insets 漂移。

IME 只由当前输入所有者所在的可见层消费：普通页面输入由 Shared 内容框处理；模态编辑输入由覆盖层宿主处理，底层 route 保持原框、不再次随 IME 缩小，且不能交互。覆盖层关闭后的转交使用相同最新窗口快照，不能先撤遮罩再补安全区。Android 系统栏图标外观也只由 Shared 平台外壳适配器写入，依据实际延伸到各系统栏下的最上层表面及其最终明暗/合成亮度，而非仅依据全局 isDark；弹层未覆盖系统区时不改下层栏外观。主题/浮层显示与系统栏外观同次状态提交，不由 feature 分别写 window flags。

多个层出现时只有最高有效层接受点击、手势、键盘和无障碍操作；透明退场不能继续交互。平台 Back/Esc/关闭按钮仍进入现有 Shared 权威，feature 不新增全局 Back 处理器。

## 4. 视觉系统与平台布局

### C 的视觉语言

实体、轻微带色的背景与分组表面；连续歌曲行、清楚的标题和少量分隔；封面而不是大品牌标语占据视觉中心。圆角用于控件/封面/面板层级，不给每首歌曲套重卡片。导航、播放、危险操作明确分离，选中状态同时有图标/文字/形状而非只靠色差。

共享规则：系统无衬线字体，沿用现有矢量图标与 EN/ZH 资源；间距阶梯 4/8/12/16/24/32/48dp。标题 28/34sp、紧凑标题 24/30、区块 18/24、正文 16/22、次级 14/20、辅助 12/16；不是在窄屏自动缩成更小字体。封面圆角 8dp、控件 10dp、分组 12dp、弹层 20dp 为统一起点。

Android 触达至少 48dp，iOS 至少 44pt；桌面可用更紧凑的视觉尺寸，但保留键盘焦点与可命中空间。200% 字号允许行高和面板增长，不截掉返回、提交、播放和恢复动作。

| 可用内容宽度 | 外壳和内容 | 播放器与详情 |
| --- | --- | --- |
| <720dp | 16dp 页边距，三项带文字的底部导航；平台安全区在其外 | 详情单页，播放器全屏层；短高优先收缩封面 |
| 720–999dp | 80dp 导航轨，24dp 页边距；没有空白详情占位 | 播放器只有在宽高都足够时分栏，否则纵向 |
| ≥1000dp | 208dp 侧栏，32dp 页边距；正文最大 1440dp | 浏览列至少 320dp、详情至少 400dp、间隔 24dp 才并排；播放器剩余至少 280dp 才保留队列栏 |

断点由公共布局策略统一提供，不允许每页自行发明。扣除窗口与系统占用后再判断；大字与最小内容宽度优先于固定列数。专辑网格以紧凑最小 128dp、宽屏最小 160dp 的卡宽自适应，16/20dp 间距。移动歌曲行通常最小 64dp/48dp 封面，桌面 56dp/40dp；都是最小值。

同一宽度规则适用于 Android 平板、iPad 和手机横屏；iOS 也可呈现导航轨/侧栏，不另做设备型号分支。宽度是扣除系统边缘后、尚未扣除应用导航的窗口可用宽度；轨/侧栏扣除后的正文继续检查最小内容宽度，不反复计算导航分类。高度影响封面、滚动与分栏可行性，不改变导航断点。例如安全区扣除后仍达 720dp 的横屏手机使用轨，避免短高屏再被底栏挤压。验收补充 844×390、800×1280、1024×1366dp，分别覆盖横屏手机和两种平板布局；取实际安全区后的分类，不按设备名钉布局。

### 平台差异

Android 使用符合其系统栏和触摸习惯的紧凑导航；iOS 尊重真实 safe area、返回与手势区域；macOS 使用真实窗口标题区、侧栏、指针 hover/右键/键盘焦点与稳定播放停靠栏。组件来源仍是现有 Miuix/Compose，不模拟假的系统窗口按钮，不引入另一套 UI 框架。

## 5. 颜色系统：模式与色板分离

| 设置维度 | 选项与行为 |
| --- | --- |
| 明暗模式 | System / Light / Dark，沿用现有偏好与系统响应 |
| 精选色板 | 苔绿（默认）、海湾蓝、陶土、鸢尾紫；各自有完整 Light/Dark 语义色 |
| Android 动态色 | API 31+ 显示「使用壁纸颜色（Monet）」开关；默认关闭；启用时由系统动态色决定当前有效色板 |
| 非支持平台 | Android API 29–30、iOS、macOS 不显示可操作 Monet 开关；继续使用用户选择的精选色板 |

这不是四个 accent：每套色板覆盖页面背景、标准/提升表面、导航、主次文字、主操作与其上文字、选中表面、边界/焦点、禁用、scrim；危险/警告/成功语义保持清楚，不能随壁纸变成无意义的装饰色。Haus 语义 token、Miuix 和现有 Material 组件使用同一解析结果，不并行保留两套主题。

规范表示是单一 Haus 解析结果：明确明暗值、所选色板、实际颜色来源及完整语义角色；不得再通过「等于某个 DarkPalette」推断 isDark。系统动态 scheme 是 Android 输入，Miuix/Material scheme 是输出适配，不反过来成为另一个主题权威。正式色板交付的必备角色为：页面/标准表面/提升表面/导航表面、主/次/反色文字、主操作/其上内容、选中表面/其上内容、装饰分隔/必要边界/焦点、禁用表面/内容、scrim，以及 error/warning/success 各自的主色/其上内容/容器/容器上内容。名称映射到现有 Kotlin API 由计划决定，不要求原型 CSS 字段成为公共 API。

正式 token、角色用途、对比度证据以及当前消费的 Miuix/Material 颜色映射已交付在[色板 token 文件](../designs/2026-10-29-platform-adaptive-ui-redesign.tokens.json)：四套精选色板 × 明暗两种模式，每套包含 29 个颜色角色和 `scrimAlpha`（共 30 个字段），另含 Android Monet 角色映射与合成校验规则。未使用的上游组件角色可由同一语义结果确定性派生，不新增无消费者的设计 token。透明叠加（尤其 scrim、禁用和选中）仍须按最终合成背景验证。

- 苔绿：低饱和绿与暖中性底；海湾蓝：冷蓝与清澈中性底；陶土：低饱和暖赭与米白/暖暗底；鸢尾紫：柔和紫与偏冷中性底。最终色值以 token 文件为准，不能从原型截图重新取色。
- 原有 theme-mode 偏好原位保留，新增色板与动态色偏好沿用现有持久化所有者。升级不重置 System/Light/Dark；新字段缺失或未知时使用苔绿、Monet 关闭。
- 开启 Monet 时保留最后选择的精选色板作为 fallback；选择任一精选色板即关闭 Monet。关闭开关恢复该精选色板，不静默改成苔绿。动态色不可用时显示「当前使用精选色板」的实际状态，保留用户的动态色意图。
- 动态能力由 Android 平台适配器以 API 31+ 和系统动态色资源能否成功解析判断；不试图检测厂商颜色是否确实来自壁纸。31+ 返回系统默认/厂商配色也视为有效「系统动态色」，文案不承诺颜色必然匹配壁纸某一点。仅在平台不支持或无法取得可用结果时报告精选 fallback；不以肉眼色差虚构「Monet 不可用」状态，也不新增重试/轮询机制。
- 系统明暗变化与壁纸色变化在应用恢复前台/配置更新时重新解析，不需要重启；不重建导航、重置播放、清空编辑/队列草稿或改变滚动位置。
- 设置页为明暗分段、四张具名色板预览、适用 Android 动态色开关和简短来源说明。预览同时显示表面、文字与动作，不只一个彩点；选中项有勾选与无障碍状态。
- 选择即时预览并保存；保存中避免冲突提交，失败回到最后持久化选择并显示可重试错误，不显示已保存的假象。无额外「保存主题」确认页。
- 正文对实际背景至少 4.5:1，大字/必要图标/焦点与交互边界至少 3:1；透明混色按最终合成背景检查。全部精选明暗组合逐项验证；动态色使用系统角色映射并验证真实支持平台样本，不宣称穷举所有壁纸。

## 6. 页面结构与完整覆盖

### 导航与浏览

底部三项为资料库、搜索、播放列表；Settings 是独立全局工具入口，详情保留返回。导航不依赖是否有播放曲目。保留 Home-rooted 单栈：Home 回根，Search/Playlists 普通 push，精确同路由不重复 push；Back 按现有历史返回，不暗中改为多栈恢复。

窗口重排、主题切换不等于退出路由：保留该路由的滚动、查询、排序筛选和选择；真实路由退出遵循既有生命期。Settings/About/引导不假装是第四个主目的地，也不错误高亮之前的主入口。

### 迷你播放器、完整播放器与下滑

- 有有效选中曲目时显示播放停靠栏，包括暂停状态；无曲目不显示假占位。紧凑约 64dp、桌面约 80dp，排版允许随大字增长。
- 点曲目身份展开，播放按钮只播放/暂停；空间允许才显示下一首。队列、搜索、设置不能挤成一排无层级小图标，搜索/设置仍属于导航。
- 完整播放器：收起/来源/更多 → 封面 → 曲目身份与收藏 → 进度与时间 → 一组主播放控制 → 队列/定时/适用歌词等次级动作。队列、定时和适用歌词都是固定位置的具名入口，不收进「更多」；顶部更多只承载该曲目现有的低频操作，无真实动作时不显示空菜单。短高优先缩封面，必要时内容滚动，不能缩小播放触达区。
- 下滑从播放器非交互表面均可开始，包括封面和空白区域，不限于把手；顶部把手与具名收起按钮共同提供发现性和无障碍替代。桌面保留显式收起与 Esc，指针拖动可作为补充而非唯一动作。
- 达到垂直方向判断后才接管：横向进度/音量等控件、按钮点击、长按和队列重排保留其手势；可滚内容未到顶部时先滚动，到顶部的后续向下拖动才可收起。平台边缘返回不被播放器全局抢占。
- 明确的短拖动未到阈值则回弹；足够位移或向下 fling 提交；阈值/速度由实施者依据现有手势 API 调整，但必须实测覆盖「轻点不关闭、横拖不关闭、短拖回弹、长拖/快速下甩关闭」。触控取消、窗口变化或更高层浮层出现时终止拖动并恢复稳定状态。
- 提交收起只调用一次现有 Shared 播放器关闭动作，不自行 pop 其他路由、不停止播放、不清空队列。返回露出原页面及原滚动位置；下层输入仅在退出结算后恢复。
- 有命名、确认、编辑或进行中受保护弹层时，不允许通过拖动底层播放器绕过它。歌词/队列内容自己的滚动与更高层 Back 优先级保留；不能用「任何地方向下滑」吞掉这些动作。
- 层级决定：紧凑 Queue 是覆盖 Controls 的独立近全高面板，面板把手/标题向下拖关闭 Queue 并回到 Controls，不收起整个播放器；队列行区域用于滚动/重排，不转交父播放器的关闭手势。Lyrics/Timer 是播放器内的阅读/设置面板，自己的返回/关闭回到 Controls，内容竖向拖动只滚动；时间轴歌词不要求先滚到播放驱动的顶部才能退出。只有 Controls 的非交互表面接受整页下滑收起播放器。宽屏侧栏遵循同一原则：拖动队列不关闭播放器。改变的是呈现与手势归属，不重写队列事务或 Back 权威。

### 歌词、队列、定时与失败

歌词只在真实非空本地歌词可用时提供入口，沿用时间轴/纯文本与来源优先级，无联网与示意文本。Back 先退出播放器内的歌词/队列或最高弹层，再收起播放器；具体选择遵循现有 Shared 仲裁，不另建一套次序。

队列在紧凑屏是近全高面板，宽屏有空间才是侧栏；保留已播放/当前/后续的既有可达内容、重排/移除/清空、重复 occurrence 和保存当前及后续的范围。保存弹层打开后曲目更换不能丢草稿；取消/Back 不保存，失败可重试，旧异步结果不得修改新会话。睡眠定时保留所有已有模式、淡出与取消，状态用文字说明。

播放失败在曲目附近显示真实错误及现有重试、跳过、仅从队列移除动作；不通过关闭播放器隐藏故障，不额外发明自动重试或修改引擎。

## 7. 每页都要设计的状态与输入

| 情况 | 呈现与下一步 |
| --- | --- |
| 首次空库 | 一段准确说明 + 一项平台正确导入动作；可跳过引导，不强制权限 |
| 当前分类为空 | 说明收藏/最近等当前视图为空，可换视图；不宣称整个库为空 |
| 扫描中 | 紧凑真实状态，不伪造百分比；已有内容仍可浏览，取消/详情走既有所有者 |
| 来源失效/扫描失败或取消 | 来源具名、真实恢复动作；与最近完成报告分离，不当作媒体已删除 |
| 无封面/缺标签/长标题 | 中性占位和既有本地化回退，艺术家/标题可读；不拿概念插画冒充实际封面 |
| 加载/暂停/播放/结束 | 保留身份，控制可用性跟随权威状态，动画不推断已播放 |
| 播放失败 | 有对象的解释与已有恢复动作，保留队列上下文 |
| 多选/编辑/提交/失败 | 数量、取消、有效提交动作与就地错误；不双重提交，失败保留应保留的草稿 |
| 系统或浮层遮挡 | 最高有效层独占操作与焦点；退场层移除点击/手势/无障碍动作，关闭后恢复入口焦点 |

键盘 Tab/Shift-Tab 顺序跟随任务顺序，Enter/Space 可激活，Esc 使用现有仲裁。长按与拖动有明确菜单/操作替代。EN/ZH、200% 字号、减少动态效果、读屏名称/状态和焦点恢复纳入同一设计，不最后补丁。

动效以 150–220ms 的层级反馈为起点；减少动态效果时用无大位移的切换，仍保证同一安全区和结算规则。播放器交互拖动与预测 Back 的中间状态必须可取消，不靠动画完成回调重建业务状态。

减少动态效果来自系统而非新增应用偏好：Android 跟随系统动画禁用信号，iOS 跟随 Reduce Motion，macOS 跟随系统减少动态效果。平台 UI 适配提供中性能力并响应前台/设置变化，Shared 统一传入动效策略；不加第三套外观开关或偏好存储。具体桥接 API 留给实施计划，但三平台来源与动态更新都属于范围。

## 8. 所有权与干净切换

- `:core:ui`：语义色、排版、间距、形状、公共行/控件/面板规则；不持有业务仓库或路由栈。
- `:shared`：主题偏好/平台结果装配、窗口与 Insets 归属、导航与覆盖层/Back、跨 feature 生命周期、公共入口和 iOS facade。
- Library/Playlists/Search/Now Playing/Settings/Onboarding：各自页面、局部状态和 EN/ZH 文案，使用显式参数接入外壳，不取服务定位器。
- Android actual/宿主提供系统动态色能力和系统栏适配；通用模型不暴露 Android Context。iOS/JVM 使用精选色板并报告真实窗口环境。
- 延续当前实际可运行的 Shared 导航与 Back，不借此次设计启用被放弃/未完成的 Miuix 导航提案。
- 每个落地切片迁移全部调用点、资源与相应合约；不留 A/C 长期运行模式、旧主题别名或两套 Insets 规则。变更公共入口或资源所有权时同步 architecture/ADR。
- 数据库 persisted schema 本轮不变；新增外观偏好进入现有偏好存储而不是 SQLDelight 新表。

| 业务回归 | 六视图、可见顺序播放、选择/元数据、静态/智能/文档操作、队列重复与保存草稿、歌词/定时、来源恢复/扫描报告、失败动作与 Back |
| 工程 | 受影响行为测试、格式/静态/架构检查与 `./init.sh`，结果和阻塞按实际输出记录；OpenSpec 严格验证与引用路径检查 |

Insets 和手势修复必须先有失败前证据，再有相同路径修复后证据；优先保留捕获消费者可见边界/交互的回归，不用源码字符串或实现细节测试。每个非平凡切片必须运行真实表面，不能只有单元测试或 HTML 原型。

实现者运行自动化与可用平台烟测；用户负责最终手工视觉/读屏/真实设备/听感与系统控制验收。没有执行的矩阵项保持未验证、未接受，不能用旧延期决定自动豁免本次新验收，也不能把设计审批当作验收。
